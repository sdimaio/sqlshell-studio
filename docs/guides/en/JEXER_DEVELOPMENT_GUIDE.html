Jexer Development Guide

Practical manual for building TUI applications in Java with Jexer
Teaching style inspired by classic Borland Turbo Vision manuals
Working version: 1.2
Reference repository: https://codeberg.org/AutumnMeowMeow/jexer
Companion documents: JEXER_COMPONENT_REFERENCE.md, JEXER_COOKBOOK.md
Examples follow the Jexer 2.0 API as read from the reference repository.

Preface

Jexer is a Java library for building rich text user interfaces inside a terminal. This guide is meant to teach how to structure real applications, not just list classes.

1. What Jexer Is

Jexer is a TUI library with windows, focus, keyboard and mouse events, and redraw management. It is useful for dashboards, data browsers, internal tools, and terminal-native utilities.

Back to top

2. Mental Model

  • TApplication: the application
  • TWindow: a window
  • Widget: a control
  • Events: keyboard and mouse input
  • Model/Service: logic outside the UI

The UI should not be the data model.

4. First Application

package app;

import jexer.TAction;
import jexer.TApplication;
import jexer.TWindow;
import jexer.backend.BackendType;

public class HelloApp extends TApplication {

    public HelloApp() throws Exception {
        super(BackendType.XTERM);

        final TWindow window = addWindow("Hello Jexer", 2, 2, 50, 12);
        window.addLabel("Welcome to Jexer", 2, 2);
        window.addLabel("This is a real TUI window.", 2, 3);
        window.addButton("Exit", 2, 5, new TAction() {
            @Override
            public void DO() {
                exit();
            }
        });
    }

    public static void main(String[] args) throws Exception {
        new HelloApp().run();
    }
}

11. Data and Application State

private Customer readForm() {
    Customer c = new Customer();
    c.setName(nameField.getText());
    c.setEmail(emailField.getText());
    return c;
}

private void writeForm(Customer c) {
    nameField.setText(c.getName());
    emailField.setText(c.getEmail());
}

12. Validation

private void validate(Customer c) {
    if (c.getName() == null || c.getName().isBlank()) {
        throw new IllegalArgumentException("Name is required");
    }
    if (c.getEmail() == null || !c.getEmail().contains("@")) {
        throw new IllegalArgumentException("Invalid email");
    }
}

14. Custom Widgets

public class StatusPanel extends TWidget {
    private String title = "";
    private String value = "";

    public StatusPanel(TWindow parent, int x, int y, int width) {
        super(parent, x, y, width, 3);
    }

    public void setTitle(String title) { this.title = title; }
    public void setValue(String value) { this.value = value; }

    @Override
    public void draw() {
        putStringXY(0, 0, "+------------------+");
        putStringXY(0, 1, "| " + title + ": " + value);
        putStringXY(0, 2, "+------------------+");
    }
}
Drawing primitives may vary slightly by version. The pattern is what matters: small state, clear setters, rendering separated from business logic.

20. Final Checklist

  • small callbacks
  • keyboard-first workflow
  • validation present
  • resize tolerated
  • clear layout and coherent colors
